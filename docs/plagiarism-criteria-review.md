# 음악 저작권 판단 기준과 현재 엔진 검토

검토일: 2026-11-02. 아래 법적 부분은 국내 판례의 저작권 침해 판단 요건에 관한 정리이며, 알고리즘 점수를 법적 판정으로 전환하는 규칙이 아니다. 엔진 구현 전에 이 조사를 충분히 마치지 못했다. 기존 코드는 후보 검색·작업 처리의 기준선으로 평가한다.

후속 구현: 아래 코드 비교표와 반례는 기존 chroma 방식의 진단 기록이다. 이를 바탕으로 256쌍의 합성 평가와 별도의 선율·음 길이 실험 방식을 추가했다. 실제 보컬·관용적 표현·창작성·의거관계의 판단까지 해결한 것은 아니다. [구현·평가·남은 한계](melody-review-experiment.md)

## 확인한 국내 판단 기준

**보호되는 표현인지 먼저 확인한다.** 대법원 2015. 8. 13. 선고 2013다14828 판결은 곡 전체가 창작물이어도 문제 된 일부가 보호되는 창작적 표현인지 따로 살펴야 한다고 판단했다. 멜로디를 중심으로 리듬·화성의 결합을 고려한다. 이 사건에서는 원고 대비 부분의 창작성에 대한 심리가 부족했다는 이유로 원심이 파기·환송됐다. 검색에 나오는 이전 1심의 표절 인정 요약만으로 결론을 옮기면 안 된다. [대법원 판결 원문](https://www.law.go.kr/LSW/precInfoP.do?precSeq=179090)

**의거관계와 실질적 유사성을 살핀다.** 수원지법 2006. 10. 20. 선고 2006가합8583 확정판결은 기존 창작적 표현의 이용, 의거관계, 실질적 유사성을 요건으로 설명한다. 멜로디와 함께 리듬·화성·박자·템포를 고려하고, 대비 부분이 곡에서 차지하는 질적·양적 중요성도 보았다. 접근가능성·공표 경위 등은 오디오 특징만으로 판단하는 정보가 아니다. 이는 지방법원 판결이며 대법원 판결과 구분한다. [음악저작물 판결 원문](https://law.go.kr/LSW/precInfoP.do?precSeq=70591)

확인한 판례를 바탕으로 한 설계 해석은 다음과 같다. 특정 사건의 8소절 비교를 모든 음악에 적용되는 고정 마디 수로 일반화하지 않는다. 비슷한 초 수나 비율 하나로 보호성·질적 중요성을 대체하지 않는다. 현재 10초 창·거리 0.18은 구현 파라미터이며 법적 기준이 아니다. 흔한 코드 진행이라는 이유만으로 결합된 전체 표현의 보호 여부까지 자동 결론 내리지 않는다.

## 연구에서 확인한 기술적 구분

chroma는 옥타브가 다른 같은 pitch class의 정보를 합친다. 이를 다성 음원 전체에서 추출하는 현재 방식에는 보컬·반주·배음이 함께 들어가므로 주선율의 개별 음정·상하 진행을 직접 추출한 것이 아니다. 이로부터, 반주나 화성의 유사성이 주선율 비교를 대신할 수 있다는 위험을 추론할 수 있다. [AudioLabs의 chromagram 설명](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C3/C3S1_SpecLogFreq-Chromagram.html)

MelodySim 연구는 멜로디를 유지하면서 악기·반주 등을 바꾼 데이터로 유사성을 평가한다. 논문의 데이터 내 weighted F1 0.98과 다른 MCIC 데이터의 F1 0.73은 분포가 바뀌면 성능이 달라짐을 보여준다. 해당 수치를 우리 앱의 정확도로 사용하지 않는다. 논문 역시 다성 선율 추출과 보컬·실제 사례로의 일반화가 남은 문제라고 설명한다. [MelodySim v2 논문](https://arxiv.org/html/2505.20979v2), [저자 저장소](https://github.com/AMAAI-Lab/MelodySim)

MPD-Set/BMM-Det 연구는 MIDI에서 구간 이동·음높이 이동·길이 변화·선율 변경을 다룬다. 현재 FMA의 동일 녹음 발췌 실험보다 평가해야 할 변형의 범위가 넓다. 연구 데이터의 유사/표절 라벨을 우리 서비스의 법적 침해 라벨로 바로 옮기지 않는다. [논문](https://arxiv.org/abs/2107.09889), [저자 데이터·코드](https://github.com/xuan301/BMMDet_MPDSet)

## 현재 코드와의 차이

| 검토할 사항 | 현재 동작 | 부족한 점 |
| --- | --- | --- |
| 멜로디의 구체적 진행 | 음원 전체의 contrast chroma 비교 | 주선율 분리·음정 간격·상하 진행을 직접 다루지 않음 |
| 리듬·음 길이 | DTW로 시간축을 늘이거나 줄여 정렬 | 리듬 패턴의 동일성을 독립적으로 입증하지 않음 |
| 특징적인 짧은 구절 | 최대 10초 창·5초 이동, 입력 최소 6초 | 더 짧은 동기나 창 일부만 닮은 경우의 재현율은 미검증 |
| 반복·질적 중요성 | 곡별 최저 거리 1구간 | 후렴 여부·여러 반복·곡 안의 중요성 평가 없음 |
| 관용적 표현·창작성 | 낮은 거리 후보 반환 | 공통 패턴의 빈도나 선행 표현 근거를 검토하지 않음 |
| 의거관계 | 입력·참조 오디오만 분석 | 창작·접근·이용 경위를 판단하지 않음 |
| 판단 임계값 | 거리 0.18 등 초기 상수 | 독립 검증 집합에서 오탐·누락 기준을 보정하지 않음 |

DTW나 chroma를 사용했다는 것만으로 법적 판단 기준을 구현했다고 말할 수 없다. 기존 32개 테스트는 저장·중복·버전·복구 등의 소프트웨어 동작을 주로 검증한다. 기존 FMA 통제 실험의 원곡 검색 성공도 재연주·새 작곡의 유사성이나 법적 침해 탐지 성공이 아니다.

## 직접 확인한 반례

별도로 쓴 두 음열과 코드 반주를 합성했다. 반주 각 음의 진폭은 0.12, 주선율은 0.04로 두어 반주가 강한 조건을 만들었다. 한 기준곡만 색인하고 각 질의의 7~17초를 비교했다. 이는 특정 혼합 조건의 통제 진단이며 실제 음악 전반의 오류율이나 법적 정답 라벨이 아니다.

| 질의 | 현재 엔진 결과 |
| --- | --- |
| 멜로디·반주 동일 | 후보 반환, 거리 0.001047 |
| 멜로디 다름·반주 동일 | 후보 반환, 거리 0.121637 |
| 멜로디 동일·반주 다름 | 후보를 찾지 못함 |

즉, 현재 점수는 주선율의 유사성만을 측정한다고 설명할 수 없다. 멜로디가 다른 곡도 음악적 화성 유사 후보일 수는 있으므로 이것을 곧 법적 오판율로 계산하지 않는다. 그러나 멜로디 검토가 핵심인 제품 목적에는 중요한 한계다. [측정 데이터](melody-sensitivity-probe.json), 재현 코드: `services/backend/app/probe_melody_sensitivity.py`.

```bash
PYTHONPATH=services/backend .venv/bin/python -m app.probe_melody_sensitivity
```

## 다음 구현의 평가 조건

먼저 다음 대조군을 포함하는 음악적 평가 집합을 만든다. 이 단계의 정답은 멜로디·구간의 유지/변경 정보이고 법적 표절 판정이 아니다.

1. 동일 음원의 발췌·재인코딩·이조·템포 변화: 기존 검색 기능의 회귀 기준.
2. 같은 멜로디와 다른 반주·악기·음량 균형: 주선율 유사성 유지에 대한 검증.
3. 다른 멜로디와 같은 코드·드럼·악기·장르: 구체적인 선율과 공통 배경의 구별.
4. 일부 음 변경, 짧은 구절 삽입, 구절 위치 이동·반복: 구간 위치와 길이의 정확성.
5. 재연주·보컬·실음원 쌍: 합성 실험과 실제 음원의 차이. 이용 가능한 원본과 음악적 검토 근거를 확보한 범위에서 수행.

같은 원곡의 모든 파생본은 같은 데이터 분할에 둬 누출을 막는다. 개발·임계값 보정·최종 검증 집합을 구분하고 후보 재현율, 정밀도/재현율, 구간 오차, 처리 시간을 따로 기록한다. 결과가 애매하거나 모델이 추출에 실패한 경우를 후보 없음과 구분한다.

그 다음에 주선율 추출·선율 인식 임베딩을 현재 엔진과 같은 집합에서 비교한다. 모델 이름이나 논문 수치만으로 채택하지 않는다. 보컬·반주의 다성 문제, 모델·가중치·데이터 조건, 로컬 메모리·지연도 함께 검증한다. 리듬과 화성은 보조 근거로 분리하며 단순 가중합을 표절 확률로 부르지 않는다.

출력은 검토할 양쪽 구간, 선율·리듬 등 비교 근거, 검색 범위와 불확실성을 제공하는 방향으로 발전시킨다. 관용적 패턴의 빈도는 검토 보조 정보이지 창작성의 자동 법적 판정이 아니다. 의거관계·보호성·허락 여부·최종 침해 판단은 오디오 점수와 분리한다.

## 이번 작업의 변경 범위

판례·연구 조사, 현재 코드 검토, 로컬 합성 진단과 문서 정리를 했다. 운영 검색 알고리즘·임계값·기존 결과는 변경하지 않았다. 새 모델·대형 데이터 다운로드, 유료 API 호출, 결제는 하지 않았다.
