# AutoMusic

프롬프트로 보컬·가사가 있는 노래를 생성하고, 저장한 음원을 듣고 다운로드하는 로컬 개발 버전입니다.

현재 **실제 생성 API 연결 코드 → 요청·상태·음원 저장·재생 → 곡별 수정본 관리 → 사용자 요청 유사 구간 검사**까지 구현했습니다. 실제 보컬 생성은 아직 검증 전이며 외부 등록은 후속 단계입니다. 유사도 검사를 자동 실행하지 않습니다.

현재 목표는 **사용자 본인만 사용하는 개인용 도구**입니다. SQLite와 로컬 파일 저장소를 유지하고 음악 생성·버전 관리·유사도 검사에 집중합니다. 회원가입·다중 사용자 격리·구독 결제는 현재 구현 범위에서 제외합니다. 생성 API 선택은 검토 중입니다.

기존 chroma·DTW 검색의 반주 의존 반례를 바탕으로 **선율·음 길이를 따로 비교하는 실험 방식**을 추가했습니다. 직접 합성한 256쌍으로 평가했고, 실제 보컬 노래·법적 표절 판정의 정확도는 아직 검증되지 않았습니다. [실험 결과·사용법](docs/melody-review-experiment.md) · [판단 기준 검토](docs/plagiarism-criteria-review.md)

## 빠른 시작

필수: Node.js 20.9 이상, Python 3.9 이상, npm. 신규 환경은 Python 3.12 권장.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r services/backend/requirements-dev.txt
npm ci
cp .env.example .env
npm run dev
```

접속: http://127.0.0.1:3000 · API 문서: http://127.0.0.1:8000/docs

`npm run dev`는 API·생성 워커·분석 워커·웹을 함께 시작하며 Ctrl+C로 함께 종료합니다. 저장 기록은 `data/automusic.db`, 음원은 `data/audio/`에 남습니다. 첫 실행에는 Docker가 필요하지 않습니다.

## 실제 보컬·가사 생성

루트 `.env`에 본인의 Music API 접근 권한이 있는 ElevenLabs API 키를 설정한 뒤 개발 서버를 재시작합니다.

```dotenv
ELEVENLABS_API_KEY=your-key-here
ELEVENLABS_MODEL_ID=music_v2_5
```

웹의 생성 방식을 **ElevenLabs Music**으로 선택합니다. 실제 생성은 연결 계정의 사용량을 소모합니다. 기본 모델은 `music_v2_5`이며 공식 `POST /v1/music/plan`에서 구성을 준비한 다음 `POST /v1/music`로 음원을 받습니다. 직접 입력 가사는 원문을 보존해 composition plan에 전달합니다. 보컬 요청을 제공자에 전달하지만 실제 가창 품질·언어 발음·가사 반영도는 실음원으로 검증해야 합니다.

- [음악 생성 API](https://elevenlabs.io/docs/api-reference/music/compose)
- [곡 구성 API](https://elevenlabs.io/docs/api-reference/music/create-composition-plan)

제공자 비교와 향후 선택 기준은 [음악 생성 AI 조사](docs/music-generation-provider-research.md)에 정리했습니다. 현재 연결은 로컬 개발 검증용이며, 서비스 제공·외부 음원 유통 범위는 제공자와 플랜별 조건을 확인해야 합니다.

API 키가 없으면 실제 생성은 비활성화되고 API도 요청을 거절합니다. 브라우저에는 API 키가 전달되지 않습니다.

## 키 없이 실행 흐름 확인

생성 방식을 **로컬 데모**로 직접 변경하면 저장·재생·다운로드 흐름을 확인할 수 있습니다. 데모는 Python으로 합성한 짧은 연주음이며 AI 생성·보컬·자동 가사 기능이 아닙니다. UI·API 기록에도 데모로 표시합니다. `ALLOW_DEMO=false`로 비활성화할 수 있습니다.

실제 ElevenLabs 호출을 수행한 검증과 데모 검증은 구분합니다. API 키가 없는 상태의 자동 테스트는 외부 유료 API를 호출하지 않습니다.

## 구조와 현재 한계

### 곡별 버전 관리

1. `내 곡`에서 곡을 선택하고 `버전 이력`에서 V1·V2 등 원하는 음원을 선택합니다.
2. `V1 기준으로 수정` 같은 버튼을 누르면 해당 버전의 제목·프롬프트·가사·설정을 입력 화면으로 불러옵니다.
3. 내용을 바꾸고 `새 버전 만들기`를 누르면 같은 곡의 다음 버전으로 저장됩니다. 데모에서는 `데모 수정본 만들기`로 표시합니다.
4. 원래 음원과 설정은 보존됩니다. V1에서 V2를 만든 뒤 V1을 다시 수정하면 V3가 되고, 기준 버전이 V1이었다는 관계도 남습니다.
5. 자동 생성된 실제 가사가 있으면 수정 화면에서 직접 입력 모드로 불러와 유지·수정할 수 있습니다. 다시 자동 생성 모드를 선택할 수도 있습니다.

`새 세션`은 수정 모드를 해제하고 별개의 새 곡을 만듭니다. 이전 버전의 `가사·생성 설정 보기`에서 저장된 입력을 확인할 수 있습니다. 현재 수정은 재생성 방식이며 파형 직접 편집 기능은 포함하지 않습니다.

기존 `productions` 데이터와 파일·재생 URL은 그대로 두고 `songs`·`song_versions` 연결 테이블만 추가합니다. 서버 시작 시 버전 정보가 없던 기존 제작 기록은 각각 독립된 곡의 V1로 연결됩니다. 반복 시작해도 중복 연결되지 않습니다.

### 사용자 요청 유사 구간 검사

현재 로컬 비교 DB에는 엄격한 CC BY/CC0 허용 목록으로 고른 **FMA Small 74곡**이 준비되어 있습니다. 원곡 전체가 아닌 30초 데이터셋 클립과 비교합니다. 직접 생성한 노래를 검사하려면 실제 생성 API 연결이 필요하지만, 엔진 검증과 데모 음원 검사는 유료 생성 API 없이 가능합니다.

1. 재생 가능한 V1·V2 등의 버전을 선택합니다.
2. `유사 구간 검사`에서 검사 방식을 고르고 검사 버튼을 누릅니다. 기본값은 기존 음악 특징 검색이며 `선율·음 길이 비교 · 실험`도 선택할 수 있습니다. 생성 완료 시 자동 실행하지 않습니다.
3. 분석 워커가 처리한 뒤 해당 버전에 결과를 저장합니다. 다른 버전 재생·생성과 독립적입니다.
4. 후보가 있으면 내 음원과 비교 클립의 시작·종료 시각, 거리, 출처·라이선스, 구간 재생을 확인합니다.
5. 같은 음원·DB snapshot·알고리즘의 완료 결과는 재사용합니다. 수정본은 별도로 검사합니다.

새 환경에서 데이터 준비와 벤치마크를 실행하려면 저장소 루트에서 다음 명령을 사용합니다.

```bash
PYTHONPATH=services/backend .venv/bin/python -m app.fma --limit 100
PYTHONPATH=services/backend .venv/bin/python -m app.benchmark_similarity
```

첫 명령은 공식 ZIP의 HTTP Range로 필요한 항목만 받습니다. 100곡은 목표 상한이며 현재 정확한 라이선스 허용 목록에서 FMA Small에 해당하는 곡은 74곡입니다. 전체 7.2GiB ZIP은 받지 않습니다. 메타데이터와 원본·특징·적재 보고서는 무시 경로인 `data/corpus/`에 저장합니다. 기존 음원으로 특징을 다시 만들 때는 `app.fma --reindex`를 사용합니다.

chroma 특징의 구간별 정확 탐색으로 후보를 고른 뒤 subsequence DTW로 구간을 정렬합니다. SQLite는 메타데이터·검사 상태·결과를 저장하고, 특징은 NPZ로 저장합니다. pgvector·학습 임베딩은 아직 사용하지 않습니다. 임계값은 초기 기준이며 표절 확률이나 법적 판단을 제공하지 않습니다. [측정 결과·한계](docs/similarity-engine.md)

별도의 실험 방식은 추출한 음높이 변화와 음 길이 패턴을 비교하며, 선율 거리·음 길이 거리·양쪽 구간을 표시합니다. 특징이 부족하면 분석 불가 또는 일부 미검토로 표시합니다. 74곡의 특징을 처음 추출한 60초 데모 검사는 워커 처리 기준 15.47초였고, 같은 조건의 완료 결과는 재사용합니다. 실제 보컬 분리나 주선율 추출 정확도를 보장하지 않습니다. [256쌍 평가·보정·재현 명령](docs/melody-review-experiment.md)

### 실행 구조

```text
Next.js → FastAPI → DB에 생성 요청 저장
                       ↓
               별도 Python 워커
                       ↓
           음악 생성 API → 파일 검증·저장
                       ↓
             상태 조회 → 재생·다운로드
```

- API와 워커가 같은 프로세스의 BackgroundTasks에 의존하지 않습니다. 대기 중 작업은 DB에 남고 워커가 처리합니다.
- `Idempotency-Key`로 중복 접수를 막습니다. 입력이 다른 동일 키는 409를 반환합니다.
- 외부 생성 결과가 불명확하거나 워커의 점유 기한이 만료되면 `needs_review`로 전환합니다. 유료 호출을 자동 반복하지 않습니다.
- 지금은 SQLite와 로컬 파일 저장소를 사용합니다. `DATABASE_URL`로 PostgreSQL을 사용할 수 있으며 Docker 구성도 제공합니다. 초기 스키마만 자동 생성하며 Alembic migration과 별도 작업 큐·S3는 후속 작업입니다.
- 현재는 인증·사용자별 격리·일일 생성 비용 한도가 없는 **단일 사용자 로컬 개발용**입니다. 사용자 요청 검사는 구현되어 있으며 개발 서버는 loopback으로 바인딩됩니다.
- 워커가 종료돼도 이미 저장한 음원·기록은 유지됩니다. 실행 중이던 외부 호출은 점유 기한(15분) 만료 후 확인 필요 상태가 됩니다. 브라우저를 닫는 것과 워커를 종료하는 것은 다릅니다.

## Docker 실행

`.env`를 만든 뒤 다음 명령을 사용합니다. PostgreSQL·API·워커·웹을 실행하고 외부 공개 포트는 loopback에만 연결합니다.

```bash
docker compose up --build
```

Docker 데이터는 native 실행의 `data/`와 분리된 볼륨에 저장됩니다.

## 검증

```bash
.venv/bin/python -m pytest -q
npm run typecheck
npm run build
```

테스트는 중복 요청·입력 검증·API 키 부재·데모 전체 저장 흐름·Range 재생 요청·다운로드·재시작 후 이력·워커 중단·유료 호출 재실행 방지·공식 API 요청 형식을 검증합니다. 수정본 검증에는 이전 음원·설정 보존, V1에서의 분기, 동시 버전 번호 할당, 동시 중복 요청, 실패한 버전 이력, 기존 DB 연결과 기존 멱등 키 호환을 포함합니다. API 요청 형식은 HTTP mock으로 검증하며 실제 가창 품질 검증을 대체하지 않습니다.
